## 1. 需求核对结论（按你的答复）

| 项 | 结论 |
|---|---|
| 输入 | 一段文本 + 角色名；可选给一个视频；可选给 `start_time` / `end_time`（start 默认 `0`，end 不给则自动估计） |
| 默认角色 | **洛天依**（与 `tts_infer.py` 默认值一致） |
| 运行方式 | **先做 PyCharm 点击运行（脚本顶部参数区，与现有 `tts_run.py` 习惯一致）**；CLI 放到后续批次 |
| 两种模式 | **A. 视频模式**：把配音/字幕插进视频，输出新 mp4；**B. 无视频模式**：输出整轨 wav + `.ass`/`.srt` 字幕文件 |
| 切句 | 按标点自动切；**很短的句子两小句并成一个字幕**，一般一小句一个字幕；阈值可调 |
| 时长 | 合成前按语速粗估，合成后以实际 wav 时长排版；与 `end_time` 对不上时**自动适配 + 提示**（富余摊到停顿；不足先压停顿，仍不足则提示，可选自动微调语速重合成） |
| 原声 | **原声不变**（默认 0dB），配音正常；两者音量在前端里都可调 |
| 不重叠 | **硬约束**：音频块之间、字幕块之间都不允许重叠（排版器保证 + 前端拖拽时拦截） |
| 前端 | **网页拖拽时间轴编辑器**：视频预览 + 音频/字幕块拖拽 + 字幕样式面板 + 一键渲染 |

可行性已验证：语音走现有 `tts_server.py` 常驻服务；ffmpeg（PATH 里的 `F:\Tools\ffmpeg`，带 libass/libx264/aac）负责混音与烧字幕；FastAPI/uvicorn 环境里已有；**不需要安装任何新库**。

## 2. 总体流程

```
一段文本
   │
   ├─① 切句（按标点；短句合并；长句再切）──────────▶  句子列表
   │
   ├─② 逐句合成（复用 tts_server，得到每句独立 wav + 实测时长）
   │
   ├─③ 时间排版（不重叠硬约束 + 对 [start_time, end_time] 自动适配）
   │
   ├─④ 生成项目 JSON（可编辑的中转文件，保存全部调整）
   │
   ├─⑤ 网页编辑器（拖拽时间位置 / 字幕空间位置与样式 / 音量 / 实时预览 / 保存）
   │
   └─⑥ ffmpeg 渲染 ──▶ 模式A：成片 mp4 ｜ 模式B：整轨 wav + ass + srt
```

## 3. 技术方案

### 3.1 为什么"逐句合成"而不是整段合成

需求要求**每句音频的时间位置可独立调整**，所以每句必须独立成块（独立 wav 文件）。
代价是句与句衔接处有轻微"重新起头"感，用 0.2~0.4 秒句间停顿让其自然；若你之后对衔接不满意，备选方案见第 7 节（整段合成 + 按静音切分）。

### 3.2 时长预测（两级）

| 阶段 | 方法 | 用途 |
|---|---|---|
| 合成前（粗估） | 按语速经验值：中文 ≈ 4.2 字/秒、日语 ≈ 5.5、英语 ≈ 13 字符/秒（`speed=1.0` 时），系数可调 | 用得少（`layout.estimate_duration`；留给第 4 批 CLI 的 `--dry-run`，不占 GPU） |
| 合成后（实测） | 每句 wav 的实际时长累加 + 句间停顿 | **最终排版的唯一依据** |

### 3.3 `end_time` 适配策略（自动适配 + 提示）

设 `可用时长 T = end_time − start_time`，`需求 S = Σ每句时长 + (n−1) × 默认间隔`（默认间隔 0.3s）：

- **S ≤ T（富余）**：把 `T−S` 平均摊到每个句间停顿；
- **S > T（不足）**：先把间隔压缩到最小值（默认 0.08s）；仍不够 → 前端标红提示"超时 X.X 秒"，给两个选择：手动调整 / 点「自动压缩语速」（按 `需要/可用` 比例调 `speed_factor` 重合成全部句子，**封顶 1.25 倍速**避免声音变形）；
- **不给 `end_time`**：自动得出 `end_time = start + Σ + 间隔`，前端显示"≤ 你的视频长度 / > 视频长度"参考；
- **视频模式附加规则**：若时间轴终点超过视频长度 → 自动冻结最后一帧补齐（保证配音/字幕不被裁掉）；视频更长则保留原长度。反之若你希望音频被裁掉，之后再加开关。

### 3.4 切句规则（默认值，均可在参数区 / CLI / 前端调整）

1. **一级切分**：在 `。！？!?；;…` 及 `。」`、`。"` 等组合后断开（含引号收尾）；
2. **再切**：过长句（> 24 字）在 `，、：` 处继续切开（**一小句一个字幕**）；单独一节仍超长时按长度均衡硬切；
3. **合并**：过短句（< 5 字）与相邻句合并（这就是"很短的句子两小句一个字幕"），合并后上限 14 字；
4. **字幕文本**默认去掉句尾的 `。`、`，`，保留 `！？…`；**TTS 文本**保留全部标点（标点影响语气）；
5. 阈值：`min_chars=5`、`max_chars=24`、`merge_max=14`。

切句是启发式；不满意的地方你可以在前端里看到每句的拆分，后续可加"改单句文本并只重合成该句"（见第 7 节）。

### 3.5 不重叠约束（硬性）

- 任意两句音频区间 `[start, start+duration]` 之间间隔 ≥ `min_gap`（默认 0.08s）；
- 字幕同理；**字幕默认与自己的音频同区间**，可单独平移（给配音做提前/延后字幕用），平移后仍不许与其他字幕重叠；
- 两处保障：**排版器**保证初始状态合法 + **前端拖拽时实时拦截**（0.05s 网格吸附，冲突位置回弹并标红）。

### 3.6 语音合成：复用现有服务

- 直接调用 `tts_client.synthesize(role, text, lang, ...)` → 走 `tts_server.py`（`127.0.0.1:9881` 常驻，模型只加载一次；服务未启动时自动拉起）；
- 逐句串行合成（服务端全局锁），前端显示 `n / 总数` 进度；
- 每句 wav 存 `projects/<id>/wavs/seg001.wav`。

### 3.7 渲染：ffmpeg 一条命令

- **ffmpeg 选择**：启动时能力检测，自动挑带 libass 的（本机 = PATH 里那个）；**conda 环境内的 ffmpeg 不带 libass，不能用**（已实测）；
- **混音**（防踩坑细节已确认）：每句 wav 先 `aresample=48000` 统一采样率、转立体声（TTS 是 32k 单声道），再 `adelay` 到各自开始时间 + `volume`；与原声（`volume=原声音量`）一起 `amix=inputs=N:normalize=0`（**`normalize=0` 关键**：否则 ffmpeg 会按输入数自动压低所有音源）；最后加安全限幅防削波 → AAC 192kbps；
- **字幕**：项目 JSON → 自动生成 `.ass`（每句一条 Dialogue：`\pos(x,y)` 坐标 + 样式：字体/字号/主色/描边/阴影；画布坐标系 = 视频分辨率）；用 `ass` 滤镜烧录。**Windows 路径转义坑的处理**：渲染时工作目录切到项目目录、只传相对文件名；
- **视频**：libx264 + `+faststart`；三档导出质量：`standard`（crf18/medium/192k）、`high`（crf12/slow/256k）、`lossless`（crf0/medium/320k，**默认**，视频逐像素无损；该档 preset 只影响体积/速度、不影响画质）——编辑器「导出质量」下拉 / `text2video_run.py` 的 `QUALITY` 参数；需要补时长时用 `tpad=stop_mode=clone`；
- **模式 B（无视频）**：输出整轨 `mix.wav` + `subtitles.ass` + `subtitles.srt`（srt 顺带导出，方便传平台）。

### 3.8 网页编辑器（`web/`，http://127.0.0.1:9882，避开 tts_server 的 9881）

- **视频预览区**：HTML5 video + 字幕叠加层（按项目 JSON 实时渲染，**拖动字幕直接改空间位置**）+ 播放/暂停；播放时用 WebAudio 按时间轴调度各句 wav（音量跟随设置），拖动进度条后自动重新调度；
- **时间轴**：两条轨道（音频块 / 字幕块），拖拽平移、0.05s 吸附、防重叠；标尺与视频时长对齐；
- **属性面板**：全局（原声 / 配音音量、start_time / end_time + 重新排版、超时提示 + 「自动压缩语速」按钮）+ 单块（字幕文本、时间、音量；样式：字号、颜色、描边色/宽、阴影、x/y——留空 = 默认值，**色块直接点选即自动开启覆盖**）；单块区带「**样式/位置同步到全部字幕**」勾选框（批量改字号/颜色/描边/阴影/位置，一处修改全部生效；时间与文本不受影响）。（全局样式编辑控件已按反馈移除，样式统一走单块 + 同步勾选）
- **顶栏**：保存（自动 + 手动）、渲染（后台执行 + 进度轮询）、完成后下载成片；
- 界面中文。浏览器预览与 libass 最终烧录的字体渲染不会 100% 一致，**预览为近似、以成片为准**。

### 3.11 入口方式：先 PyCharm 参数区（✅ 已实现），CLI 后续再做

`text2video_run.py` 顶部就是「参数区」，改完右键 Run 即可（与现有 `tts_run.py` 的习惯完全一致）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `TEXT` | 示例文本 | 要配音的文本；也可填 `.txt` 文件路径（自动读取） |
| `VIDEO` | `""` | 输入视频路径；留空 = 无视频模式（只出音频 + 字幕文件） |
| `OUT` | `""` | 成片输出路径；留空 = 自动放到 `projects/<任务id>/` |
| `ROLE` | `洛天依` | 角色名（`python tts_infer.py --list` 查全部） |
| `LANG` | `zh` | zh / ja / en / ko / yue |
| `SPEED` | `1.0` | 语速 |
| `START_TIME` / `END_TIME` | `0.0` / `None` | 时间轴起点 / 终点（秒）；`END_TIME=None` 自动估计 |
| `MIN_CHARS` / `MAX_CHARS` / `MERGE_MAX` | `5 / 24 / 14` | 切句阈值 |
| `GAP` / `MIN_GAP` | `0.3 / 0.08` | 默认句间停顿 / 压缩后的最小停顿（秒） |
| `ORIGINAL_VOLUME_DB` / `TTS_VOLUME_DB` | `0.0 / 0.0` | 原声 / 配音音量（dB，0 = 不变） |
| `STYLE` | 微软雅黑 54px 白字黑边、底部居中 | 字幕默认样式（前端里还能逐句调） |

CLI（`--video / --text-file / --no-video / --dry-run` 等）在后续批次提供，参数与本表一一对应。
每次任务产出 `projects/<id>/project.json`，CLI 与网页编辑器共用同一份项目文件。

## 6. 风险与边界（提前说清）

- **句间衔接**：逐句合成在边界处有轻微起头感，用句间停顿掩盖；这是"逐句独立可调"的固有代价；
- **句子多（>50）**：ffmpeg 混音输入多、渲染慢一些（分钟级），可接受，必要时分批混音；
- **预览≠成片**：浏览器与 libass 字体渲染细节有差异，以成片为准（编辑器定位仍是像素级对应的）；
- **合成耗时**：长文本 ≈ 句数 × 1~3 秒，前端有进度显示；
- **切句是启发式**：特殊排版（表格式、无标点长文）可能切得不理想，可在前端看到并后续手动改文本；
- **合规**：沿用模型包须知（仅学习交流、公开发布前自行确认角色/声优权益）。

## 7. 可选扩展（本次不做，结构已预留）

- 多角色对话（每句指定角色）——JSON 已预留 `segments[].role` 字段；
- 前端修改单句文本并只重合成该句；
- 整段合成 + 按静音对齐切分（替代逐句合成，衔接更自然）；
- 图片 → 视频模式（`--image`，低成本）；
- 原声自动闪避（ducking）。
